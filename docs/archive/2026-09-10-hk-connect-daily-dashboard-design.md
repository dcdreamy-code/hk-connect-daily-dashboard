# 港股通每日热榜看板设计

## 目标

构建一个免费、公开、只读的港股通每日热榜。看板在收盘后更新，展示成交额、涨幅和跌幅前 30 名，并为每只股票提供简要的公司信息。

## 受众与范围

- 受众：需要快速扫描港股通当日成交和涨跌情况的个人投资者。
- 形式：无登录、无管理后台的静态网站。
- 第一版不包含盘中实时行情、K 线、完整历史数据库、自选股和用户系统。

## 数据来源与授权边界

- 港股通股票池以项目内名单为准，生成一份可版本化的代码清单。
- 日行情由数据适配器获取。第一版使用东方财富网页内部接口，只在收盘后生成前 30 名派生榜单。
- 公司简介以已获取的 Wind 结果优先，缺失时可由东方财富 F10 接口补充，并作为低频静态数据缓存。
- 前端不直连第三方接口，不暴露请求规则，不提供原始全量行情下载。
- 页面明确标注数据日期、更新时间、数据来源和“仅供信息参考”。
- 东方财富匿名网页接口没有稳定性或公开转授权承诺。项目不宣称这是官方 API；若转为商业或大规模服务，必须切换至获得公开展示授权的数据源。

## 架构

```text
每日定时任务
    -> 读取港股通股票池
    -> EastMoneyAdapter 获取收盘行情
    -> 验证日期、字段和覆盖率
    -> 计算成交额/涨幅/跌幅 Top 30
    -> 生成 public/data/daily/YYYY-MM-DD.json
    -> 原子更新 public/data/latest.json
    -> 静态看板读取 JSON
```

代码将数据抓取、标准化、榜单计算和页面展示分开。`EastMoneyAdapter` 只负责将第三方响应转换为内部行情模型，以后可以替换为 Wind 或获得授权的供应商。

## 数据模型

`latest.json` 包含：

- `tradeDate`：真实行情日期。
- `generatedAt`：生成时间。
- `source`：数据来源说明。
- `coverage`：股票池数量、成功匹配数量和覆盖率。
- `market`：上涨、下跌、平盘数量及全股票池成交额。
- `rankings.turnover`、`rankings.gainers`、`rankings.losers`：最多 30 条标准化记录。
- 每条记录包含代码、名称、收盘价、涨跌幅、成交量、成交额、当日高低价、行业和公司简介。

## 界面

- 首屏直接是看板，不设营销页。
- 顶部显示产品名、行情日期、更新时间和数据状态。
- 紧凑的市场摘要显示上涨/下跌家数、总成交额和数据覆盖率。
- 用分段控件切换“成交额”、“涨幅”、“跌幅”榜。
- 桌面端使用紧凑数据表；移动端保留排名、名称、涨跌幅和成交额。
- 点击行展开详情，展示公司简介、行业、价格区间和成交量。
- 搜索支持代码和名称，只过滤当前榜单。
- 视觉采用浅色专业行情终端风格：白底、深灰文字、红涨绿跌、高密度但易扫描。

## 错误处理

- 数据源请求设超时、有限次重试和明确的 User-Agent。
- 响应结构不符合预期、股票池覆盖率过低、交易日无法确定时，任务失败且不覆盖 `latest.json`。
- 静态页面加载失败时显示可理解的错误状态，不显示空榜单。
- 非交易日保留上一交易日数据，页面始终以 `tradeDate` 为准。

## 自动化与部署

- GitHub Actions 在交易日收盘后定时执行数据生成器，同时支持手动触发。
- 数据更新以单独提交写回仓库，Vercel 检测到提交后自动发布。
- 网站为纯静态文件，不需要付费服务器、数据库或密钥。

## 验证

- 单元测试：代码规范化、第三方字段映射、股票池过滤、排名、缺失值和覆盖率门禁。
- 数据冒烟测试：生成结果必须符合 JSON Schema，每个榜单不超过 30 条。
- 前端测试：榜单切换、搜索、详情展开、加载/空/错误状态。
- 视觉验证：桌面和移动端截图，确认无溢出、重叠、截断和空白主视图。

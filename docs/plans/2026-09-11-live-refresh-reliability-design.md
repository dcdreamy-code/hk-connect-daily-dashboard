# 港股通看板准实时刷新与收盘可靠性设计

## 目标

在个人免费项目的成本约束下，将现有盘中刷新从“可选的两分钟浏览器直连”优化为更清晰、可靠的分钟级准实时体验，同时保证收盘数据能够稳定落盘。项目不引入 WebSocket、数据库或付费行情服务。

## 方案选择

采用浏览器端一分钟轮询与轻量行情载荷。相比秒级推送，这一方案更符合榜单用途，部署成本为零，也避免引入常驻服务。相比维持现状，它减少用户看到陈旧数据的概率，并让数据时间与失败状态可见。

东方财富网页行情仅用于个人非商业原型。它没有第三方开发者 SLA，也不构成获得公开转发行情授权的证明。未来扩大访问量或商业化时，需要迁移到具有展示许可的数据源，并改为服务端集中采集与缓存。

## 数据流

1. 正式快照继续由 `public/data/latest.json` 提供，用作首次加载和收盘基线。
2. 公司简介、股票池和 AH 映射保持低频静态资源，不随每次盘中刷新重复下载。
3. 盘中行情按股票池分批请求，页面每 60 秒最多刷新一次。
4. 页面使用行情记录自身的最新时间戳判断新鲜度，而不是只显示浏览器请求时间。
5. 交易时段结束时执行一次收盘末次刷新；成功后保留最后结果并标记为收盘参考，失败时保留最后一次成功数据并明确提示。
6. 正式收盘任务在工作日 16:30 执行，并增加一次稍后的兜底任务；相同交易日内容通过现有原子写入和差异提交机制去重。

## 页面状态

顶部状态区显示数据类型、最近行情时间和数据年龄。状态至少覆盖：正在刷新、盘中数据、午间暂停、收盘数据、数据延迟、刷新失败。刷新失败不能清空现有榜单。

盘中刷新保留用户开关和浏览器偏好。页面隐藏时暂停请求，重新可见时立即检查数据。为了避免标签页定时器错过收盘边界，状态机记录是否已经尝试过当日末次刷新。

## 可靠性与验证

- 行情批次仍保留超时和一次重试。
- 覆盖率低于 80% 时拒绝替换当前榜单。
- 增加市场时段、末次刷新和数据新鲜度单元测试。
- 验证正式快照、传播图生成及现有排序、搜索行为不回归。
- 通过本地服务做页面加载与静态资源冒烟检查。

## 部署边界

当前目录没有 Git remote，因此 GitHub Actions 配置不会自动执行。代码可完成并验证，但真正启用 16:30 自动任务仍需要将该目录发布为独立 GitHub 仓库并开启 Actions；公开部署同样需要用户明确授权。
